# SEO, AEO and Analytics Audit Runbook

A repeatable audit for aliveprostudios.com: search, answer engines, redirects,
structured data, GA4, Tag Manager and Search Console. Distilled from the
2026-11-15 and 2026-11-16 audits.

**To run it,** say: *"Run the audit runbook in `docs/audits/AUDIT-RUNBOOK.md`."*
Claude reads this file and follows the sequence below. Results go in a new dated
folder, `docs/audits/YYYY-MM-DD/`. Earlier audits stay where they are, so the
new results can be compared with them.

**Suggested rhythm:** every 3 to 6 months, and after any migration, hostname or
DNS change, new section, or Tag Manager overhaul.

A version for javad.ca is at the end.

  change nothing until Javad has reviewed it.

  YouTube). Push to production only on Javad's explicit "push to production".
  Staging first, then production.

  Canadian English, no em dashes, never "honest" or "honestly", never a price,
  range or percentage for what anything costs, plain headlines.

- **Verify against the live site, not the code.** Show evidence.
- **Never sign in, switch Google accounts or enter a passkey** for Javad. Stop and ask.
- **Respect closed decisions.** The Design System C contrast trades and the
  other "ACCEPTED TRADE" rows in CLAUDE.md are not findings. Do not re-raise them.

## Sequence

### 1. Orient
- Read CLAUDE.md (especially "Traps already hit" and "Known gaps"), ANALYTICS.md,
  SITEMAP.md, TASKS.md, and the most recent dated audit folder.
- Check git status and confirm `main` and `staging` match production and staging.
- Write down what changed since the last audit. Check those areas first.

### 2. Crawl the live site
- For every sitemap URL, check:
  - status
  - `<title>`
  - meta description (120 to 160 characters)
  - canonical (its own, never the homepage's)
  - robots meta and `X-Robots-Tag`
  - one H1 with no skipped heading levels
  - `lang`
  - og and Twitter tags
  - every JSON-LD block, parsed
  - every link and image
- Every URL must show a share image when pasted. Check that each `og:image`
  loads and that its declared size is the real size.
- Find orphan pages, broken internal and outbound links, and weak internal
  linking.

### 3. Sitemap, robots.txt, llms.txt, AI crawlers
- **Sitemap:** it equals the set of live indexable pages exactly. `/sitemap.xml`
  redirects to it. `lastmod` appears only where a page has a real schema date.
- **robots.txt:** allows everything. Staging disallows all.
- **llms.txt:** generated by `scripts/postbuild.mjs`, with the same count as the
  sitemap. Spot-check that titles and descriptions match the pages.
- **Cloudflare AI Crawl Control:** report what is blocked. The decision is to
  allow all. The toggles **block** when switched on.

### 4. Redirects, hostnames, old URLs
- Test **every** rule in `dist/_redirects` live, in **both slash forms**, and
  check every target returns 200. Test all of them, not a sample.
- Test all four hostname variants: https and http, with and without `www`.
  Check deep paths and query strings.
- Pull old URLs from the Internet Archive (CDX API) and from Search Console's
  "Not found (404)" report. List every one that 404s today, with a proposed
  destination or a reason to leave it as a 404.
- Cloudflare ignores file order between overlapping wildcards. No wildcard may
  overlap another one. Verify on **staging**, not only in `npm run preview`.

### 5. Structured data and the entity
- **Organization:** description, image, logo, founder, areaServed, and `sameAs`
  with verified profiles only.
- **WebSite:** a node on every page. Every page entity is `isPartOf` it.
- **Article** (blog and case studies): image, description, author,
  `datePublished` with a time and the Toronto offset via `schemaDateTime()`,
  and `og:type` article. Only one Article per page.
- **VideoObject:** `uploadDate` with a time, and `description`.
- **Cross-site link:** Javad's founder entry and javad.ca's Person entity point
  at each other.
- `/404` is `noindex`.
- Run Google's Rich Results Test on live URLs for one page of each type.

### 6. Search Console, Analytics, Tag Manager: read-only audit
- **Search Console:**
  - property type
  - indexed vs not indexed, with reasons
  - sitemap status
  - 404 list
  - manual actions, security, HTTPS
  - users
- **Tag Manager:**
  - live version and date
  - every tag, trigger and variable
  - triggers that match a trailing-slash URL the site never serves
  - `tel:` and `mailto:` formats against what the site writes
  - duplicate or dead tags
  - access
- **GA4:**
  - data retention of 14 months
  - the internal traffic rule and data filters
  - enhanced measurement
  - unwanted referrals
  - key events with no data
  - the Search Console link pointing at the right property
  - Ads links
  - look-alike properties
  - access
- **Live page:**
  - `page_view` count per load
  - each platform actually transmitting
  - whether staging loads the production container (known gap)
- Compare everything against ANALYTICS.md and record every difference.

### 7. Report and stop
- Write `docs/audits/YYYY-MM-DD/` and publish one report artifact containing:
  - what passed
  - what needs action, ranked by severity
  - who has to act on each item
  - the decisions that are Javad's
  - what is new since the last audit and what was fixed
- Stop for review.

### 8. Second opinion
- Run an independent Codex audit of the live site without showing it the report
  (see the global CLAUDE.md for the `codex exec` form; run it in the background
  with `-o`). Merge its findings, re-check every difference yourself, and update
  the report.

### 9. Fix, in approved batches
1. **Redirects:** add them to SITEMAP.md, then build. Test every rule in the
   local preview, then on staging, then on production, in both slash forms.
2. **Code and schema:** build, run `npm run check`, and verify every page in
   `dist/`. Then staging, then production.
3. **Copy** (meta descriptions, video descriptions, anything visible):
   1. Draft from each page's own wording.
   2. Have it reviewed by `brand-voice:content-generation`.
   3. Check it by script against the content rules.
   4. Give the drafts to Javad for approval before shipping.
4. **GA4, GTM and Search Console:** make only the changes Javad approved.
   - GTM: make all changes in one workspace, test them in Tag Assistant
     Preview, then publish one named and described version.
   - Log any test conversion you cause, with its time.

### 10. Close out
- Update:
  - CLAUDE.md: current state, new traps, Known gaps
  - ANALYTICS.md: every change, with its date
  - SITEMAP.md: redirect counts
  - TASKS.md: what is left and who owns it
  - README.md: official profiles
  - the site facts table above, if anything changed
- Commit. Push only when Javad says so.
