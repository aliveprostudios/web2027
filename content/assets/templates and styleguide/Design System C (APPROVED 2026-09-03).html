Read this before signing off the palette. Orange text and lime headings both clear AA comfortably on black and both fail it on white. In black mode this system is fully accessible. (11)  Components

Nav and menu.

A minimal bar over the hero: mark, an established-since label, the mode toggle and a burger. There is no desktop dropdown; every viewport uses the same full-screen overlay.

Alive Pro
EST. 1997

Bar: 28px --gutter padding · Burger: 44px square, three 2px bars, 6px gap · Theme button: 40px circle, 1px border rgba(255,255,255,.35)

Overlay rules

  • The overlay is a direct child of <body>, never nested in <header>. A scrolled header's backdrop-filter becomes the containing block and collapses it.
  • Visibility is the hidden attribute, not opacity. .menu[hidden]{display:none}.
  • Scroll lock is html.is-menu-open. Never body.
  • Escape closes. Focus moves to the first item on open and returns to the burger on close.
  • A pageshow handler clears a stranded lock.
  • Sub-menus are an accordion, one section open at a time.

Open: aria-expanded flips on the burger, which also carries aria-controls="site-menu". Tab is not yet trapped inside the overlay; that is a known gap.

Never hardcode an aspect ratio. Each source's real aspect is fetched from the provider and applied, or the video letterboxes inside its own iframe.

Standing rules

  • One H1 per page. Heading levels never skip.
  • Tap targets 44px or larger.
  • Scroll locks go on <html>, never <body>.
  • Fixed overlays live outside .page-root; it and .hero both clip fixed descendants.
  • All animation is CSS. A global reduced-motion block kills it site-wide, so no component needs its own guard.
  • Canadian English. No em dashes anywhere.

Rules that only bite on mobile

  • Body copy never goes below 16px. iOS zooms a focused input under 16px, which throws the layout.
  • Tap targets 44px minimum, including the burger and the mode toggle.
  • No horizontal scroll at any width. Wide content gets its own overflow-x:auto container rather than widening the page.
  • Test at 375, 768 and 1440 in a real viewport. An emulated one will not catch a stuck hover state.
  • The full-screen menu is the navigation at every width, so there is no separate mobile nav to specify.

This page follows the same rules. Open it on a phone and the specimens resize with it; the guide is the demonstration.
